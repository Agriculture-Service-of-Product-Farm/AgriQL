Agriculture-native database language

AgriQL stores the measurements for a farm, a field trial, or a season, and it is the language used to query them. The record is one file, ending in .aqdb.

Why it matters

A measurement is not a plain number

Twenty-five can mean percent soil moisture, millimetres of rain, or a temperature. In a spreadsheet those values look the same. AgriQL keeps the unit with the value and rejects a sum of quantities that do not share one.

The season stays in one file

Soil readings, crop notes, water, and weather belong together. One database file can be copied, archived, and queried later. It does not depend on a pile of workbooks with slightly different column names.

The record is not the analysis tool

People already work in Excel, Python, and R. Those tools can receive a result. They are not where the measurements are kept. The database remains the record.

How it differs

A general-purpose database will store farm tables. It treats a column as numbers or text, and it is meant for any application. AgriQL is narrower, on purpose.

  • Subject. AgriQL is for agricultural measurements: soil, crop, water, weather, and sensor observations. A general-purpose database is for whatever the application needs.
  • Units. AgriQL refuses to add a length to a mass. A general-purpose database stores the numbers and leaves that check to the application.
  • The file. An AgriQL database is one .aqdb file. A general-purpose system is often a server you administer, or a file in a format that knows nothing about a field or a season.
  • Exchange. CSV, JSON, and Excel move in and out, because that is how many farms and laboratories already keep data.
  • Analysis. The Python, R, and Arrow clients return rows from a query. They do not become a second copy of the database.

AgriQL is not a replacement for every database. Use it when the thing you need to trust is an agricultural measurement.

A query

You can filter a table and summarise it. This asks for the mean soil moisture of each plant below a threshold.

IMPORT CSV 'soil.csv' INTO agriculture.soil;

SELECT plant_id, AVG(soil_moisture)
FROM agriculture.soil
WHERE soil_moisture < 25
GROUP BY plant_id;

Clients

Each client sends a query to AgriQL and returns the rows.

  • R
  • Arrow, for taking a result into an analysis file
