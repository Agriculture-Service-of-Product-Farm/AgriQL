Agriculture-native database language 1.0

AgriQL stores the measurements for a farm, a field trial, or a season, and it is the language used to query them. The record is one file, ending in .aqdb.

Why it matters

A measurement is not a plain number

Twenty-five can mean percent soil moisture, millimetres of rain, or a temperature. In a spreadsheet those values look the same. AgriQL keeps the unit with the value and rejects a sum of quantities that do not share one. A length is not added to a mass. Millimetres and metres can be added, because they are both length.

The season stays in one file

Soil readings, crop notes, water, and weather belong together. One database file can be copied, handed to a colleague, and queried months later. The archive does not depend on several workbooks whose column names have drifted apart.

The record is not the analysis tool

People already work in Excel, Python, and R. Those tools can receive a result. They are not where the measurements are kept. If a notebook is lost, the database file is still the record.

An imported table remembers its source

When a CSV, JSON, or Excel file is imported, AgriQL records where that table came from. A later reader can see that the rows were not typed in by hand.

How it differs

A general-purpose database will store farm tables. It treats a column as numbers or text, and it is meant for any application. AgriQL is narrower, on purpose.

  • Subject. AgriQL is for agricultural measurements: soil, crop, water, weather, and sensor observations. A general-purpose database is for whatever the application needs.
  • Units. AgriQL refuses to add a length to a mass. A general-purpose database stores the numbers and leaves that check to the application, where it is easy to skip.
  • The file. An AgriQL database is one .aqdb file for a farm or a study. A general-purpose system is often a server you administer, or a file format that knows nothing about a field or a season.
  • Exchange. CSV, TSV, JSON, and Excel move in and out, because that is how many farms and laboratories already keep data.
  • Analysis. The Python, R, and Arrow clients return rows from a query. They do not become a second copy of the database.

AgriQL is not a replacement for every database. Use it when the thing you need to trust is an agricultural measurement.

What you can do

  1. Open a database file, or create one for a farm or a trial.
  2. Import a table from CSV, TSV, JSON, or Excel.
  3. Filter that table and summarise it: count, minimum, maximum, average, and standard deviation.
  4. Ask which values are missing, and which numbers sit far from the rest.
  5. Ask whether a time series has gaps.
  6. Export the table back to CSV, JSON, or Excel.
  7. Read the same file from Python or R, or write the rows to an Arrow file for further work.

A query

Bring in a soil sheet, then ask for the mean moisture of each plant below a threshold. The result can be written back to Excel.

IMPORT CSV 'soil.csv' INTO agriculture.soil;

SELECT plant_id, AVG(soil_moisture)
FROM agriculture.soil
WHERE soil_moisture < 25
GROUP BY plant_id;

EXPORT XLSX agriculture.soil TO 'soil.xlsx';

A quality check on the same table reports empty values and unusual numbers:

PROFILE agriculture.soil;

Clients

Each client sends a query to AgriQL and returns the rows. Install the client you use. The database file stays AgriQL.

Python

import agriql

db = agriql.connect("farm.aqdb")
rows = db.query("""
    SELECT plant_id, AVG(soil_moisture)
    FROM agriculture.soil
    GROUP BY plant_id
""").to_records()

If pandas or Polars is installed, the same result can be turned into one of those tables. That conversion is optional.

R

library(agriql)

db <- aqdb_connect("farm.aqdb")
aqdb_frame(aqdb_query(db, "SHOW SCHEMAS;"))

Arrow

Arrow is for moving a result into an analysis file. It does not open the database.

agriql-arrow write soil.tsv soil.arrows
agriql-arrow read soil.arrows

Limits

These are the present boundaries, not a promise of later work.

  • A summary query reads one table. It does not join several tables.
  • CSV, TSV, JSON, and Excel are accepted. Parquet, and a spreadsheet that lives only online, are not.
  • Python, R, and Arrow do not contain the database. They talk to AgriQL.
  • AgriQL is under active development. The behaviour above is what you can rely on now.
